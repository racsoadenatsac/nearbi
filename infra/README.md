# nearbi-infra

OpenTofu infrastructure for nearbi.ai on AWS: Route 53, ACM, CloudFront, S3, API Gateway, Lambda, DynamoDB.

Part of the NEAR Hackathon one-agent research shop. See `rs-docs/ARCHITECTURE.md`. The app itself is
`../nearbi-app`; its README ("Deploy: AWS resources", "Request routing") is the spec this repo implements.

## Layout

```
tofu/                 one root module (state: s3://nearbi-tfstate-916489698349/nearbi-infra/phase-1.tfstate, S3 lockfile)
  dns.tf              Route 53 zone, ACM cert + DNS validation records, apex/www aliases (gated)
  storage.tf          S3 nearbi-site (OAC only) + nearbi-content (private, versioned), DynamoDB table nearbi
  secrets.tf          random SESSION_SECRET / ADMIN_TOKEN / ORIGIN_VERIFY_SECRET -> SSM SecureString /nearbi/app/*
  app.tf              Lambda nearbi-app, IAM role, log group, HTTP API ($default stage + route)
  cdn.tf              CloudFront (static via OAC, app via API Gateway + x-origin-verify), index-rewrite function
  scheduler.tf        EventBridge Scheduler payment sweep -> Lambda
  agent.tf            IAM user nearbi-agent (rs-agent, unattended) + least-privilege inline policy
  functions/          CloudFront Function source
bin/
  build-app.sh        builds ../nearbi-app/dist/lambda/index.mjs with the app's Docker wrapper
  sync-site.sh        aws s3 sync ../nearbi-app/public -> site bucket, then invalidates CloudFront
  seed.sh             runs the app's seed script (report catalog) in node:22-slim against the table
  verify.sh           curl smoke test through CloudFront
```

## Deploy

```bash
export AWS_PROFILE=nearbi                 # SSO; run `aws sso login` yourself if it expired
bin/build-app.sh                          # app bundle (Docker, no host node)
tofu -chdir=tofu init
tofu -chdir=tofu plan -out=tfplan && tofu -chdir=tofu apply tfplan
bin/sync-site.sh                          # static site
bin/seed.sh                               # catalog entry
bin/verify.sh                             # smoke test against the cloudfront.net URL
```

## Switching on the custom domain (`cert_validated`)

Phase 1 runs on the `*.cloudfront.net` URL. To go live on nearbi.ai:

1. At Namecheap, set custom DNS for nearbi.ai to the four `tofu -chdir=tofu output nameservers`.
2. Wait until ACM shows the cert as `ISSUED`:
   `aws acm describe-certificate --certificate-arn $(tofu -chdir=tofu output -raw certificate_arn) --query Certificate.Status`
3. `tofu -chdir=tofu apply -var cert_validated=true` (or put it in a gitignored `terraform.tfvars`). This adds
   the validation waiter, the CloudFront aliases `nearbi.ai` + `www.nearbi.ai` with the ACM cert, the
   Route 53 A/AAAA alias records, and adds the public origins to the app's `APP_ORIGIN`.

## Security notes

- Buckets: Block Public Access, BucketOwnerEnforced, SSE-S3, TLS-only bucket policy. The site bucket is
  readable only by this distribution (OAC + `AWS:SourceArn`).
- The API Gateway URL is not a bypass: the app rejects requests without the `x-origin-verify` header
  CloudFront adds (403). API Gateway default-route throttling (20 rps / 40 burst) caps cost.
- Lambda role: logs on its own log group; `GetItem/PutItem/UpdateItem/DeleteItem/Query/ConditionCheckItem`
  on the table; `s3:GetObject` on `nearbi-content/reports/*` and `s3:ListBucket` on the bucket. Nothing else.
- Secrets are generated by `random_password`, stored in SSM SecureString (`/nearbi/app/*`, aws/ssm key) and
  injected into the Lambda environment, because the app reads them from env only (no SSM at cold start).
  **The tofu state contains them**; the state bucket is private, encrypted and versioned. Rotate with
  `tofu apply -replace=random_password.session_secret` (signs everyone out) etc.
- DynamoDB has deletion protection on. To destroy, set `deletion_protection_enabled = false` first.

| Route 53 queries, ACM, CloudFront Function, SSM Standard, OAC | ~0 |

## Payments (NEAR Intents 1Click) — LIVE on mainnet since 2026-11-03

The Lambda gets `INTENTS_MODE` (`var.intents_mode`, default **`live`**), `SETTLEMENT_RECIPIENT`
(`var.settlement_recipient`, default **`forwarder.nearbi.near`**), `SETTLEMENT_ASSET` (`var.settlement_asset`,
native USDC on NEAR `nep141:17208628…6133a1`) and `SETTLEMENT_DELIVERY` (`var.settlement_delivery`, default
`transfer`: plain `ft_transfer`, refundable). `intents_mode = "live"` fails validation here, and the app
refuses to start, unless the recipient is a mainnet NEAR account. To go back to preview: `-var intents_mode=dry`
(open live payments are still swept). `ONECLICK_JWT` (optional partner key, only lowers fees) is not wired
yet; add it to `local.secrets` when there is one. Details: nearbi-app README "Payments".

### Background payment sweep (`tofu/scheduler.tf`)

EventBridge Scheduler `nearbi-payment-sweep` (`var.payment_sweep_schedule`, default `rate(1 minute)`, UTC,
no flexible window, no retries, max event age 60 s) invokes `nearbi-app` directly with the input
`{"nearbiTask":"sweep-payments"}`. Its role `nearbi-app-payment-sweep-scheduler` can only
`lambda:InvokeFunction` on that function and can only be assumed by `scheduler.amazonaws.com` from this
account (`aws:SourceAccount`). No new Lambda permissions were needed: the sweep uses `Query`/`GetItem`/
`UpdateItem`/`PutItem`/`DeleteItem` on the same table. Disable with `-var payment_sweep_enabled=false`
(the checkout page still polls). Evidence that it runs, one line per minute:

```bash
aws logs filter-log-events --log-group-name /aws/lambda/nearbi-app --filter-pattern '"sweep-payments"' \
  --start-time $(( ($(date +%s) - 600) * 1000 )) --query 'events[].message' --output text
```

Cost: 43 200 invocations/month of a ~100 ms, 512 MB Lambda plus one DynamoDB Query each: well inside the
free tier, < $0.10/month otherwise.

### Forwarding (not in AWS)

1Click delivers USDC to `forwarder.nearbi.near`; moving it into `splitter.nearbi.near` needs the forwarder's
function-call key, which stays in the operator Mac's Keychain. `rs-agent bin/forwarder-runner` runs there
as the IAM user `nearbi-agent` (below): it reads the `FWDQ` queue items and `PAY#` items, writes `forwardedTx`
and deletes the queue item.

## Agent identity: IAM user `nearbi-agent` (`tofu/agent.tf`, applied 2026-11-04)

The unattended shop agent on the operator's Mac (rs-agent `bin/agent-tick`, `bin/forwarder-runner`, `bin/agent-orders`,
rs-ledger `bin/publish`) runs as this user instead of the operator's SSO session, so nobody has to log in again. The
user has no console login profile and no group. Its inline policy `nearbi-agent-least-privilege` allows only the aws
CLI calls those scripts make:

- DynamoDB `nearbi`: `Query`/`GetItem` with `dynamodb:LeadingKeys` ∈ `FWDQ`, `ORDERQ`, `PAY#*`, `ACCT#*`; `UpdateItem` on
  `PAY#*`; `DeleteItem` on `FWDQ`. The table has no indexes. No `Scan`, `PutItem` or table-level actions.
- SSM: `GetParameter` on `/nearbi/app/ADMIN_TOKEN` only (aws/ssm key; its key policy covers the decrypt), and
  `DescribeParameters` on `*` (no resource-level support; metadata only).
- S3: `GetObject`/`PutObject` on `nearbi-content/<content_prefix>reports/qa-*` + `ListBucket` on `nearbi-content`
  (HeadObject of a missing key must be 404); `PutObject`/`DeleteObject` on `nearbi-site/ledger/*` + `ListBucket` on
  `nearbi-site` limited to `s3:prefix` `ledger/`, `ledger/*`.
- CloudFront: `CreateInvalidation`/`GetInvalidation` on this distribution. `sts:GetCallerIdentity`.

No `lambda:GetFunctionConfiguration`, because it would expose every app secret in the Lambda environment: rs-agent
has the content bucket name built in. No `iam:*`, not even for its own keys.

**The access key is deliberately not a tofu resource**, so its secret never enters the state. It was created once
with `aws iam create-access-key` and piped into the Mac's login Keychain (item `nearbi-agent-aws`); the aws CLI reads it
through `credential_process` (rs-agent `bin/aws-keychain-credentials`, profile `nearbi-agent`).

Rotate (zero downtime, 2 keys max) / revoke, with `AWS_PROFILE=nearbi`. The full procedure is in rs-agent README
"Rotate or revoke the key":

```bash
aws iam list-access-keys --user-name nearbi-agent
aws iam create-access-key --user-name nearbi-agent ...   # piped into the Keychain, see rs-agent README
aws iam update-access-key --user-name nearbi-agent --access-key-id <old> --status Inactive
aws iam delete-access-key --user-name nearbi-agent --access-key-id <old>
```

Revoking a key (Inactive/delete) stops the agent at its next tick (exit 3). Removing the user: delete its access keys
first (tofu does not own them, so `aws_iam_user` deletion fails while keys exist), then remove `agent.tf` and apply.
Changing the policy: edit `agent.tf`, plan (expect only `aws_iam_user_policy.agent` to change), apply.

## Free reports (static, public)

`local.free_report_slugs` in `tofu/cdn.tf` lists the public reports (`near-users-vs-bots`, `near-thesis`). Each
gets two static behaviors (`/reports/<slug>` and `/reports/<slug>/*`) ahead of the gated `/reports/*` rule, the
index-rewrite function 301s the slash-less URL, and the same list is passed to the Lambda as `FREE_REPORT_SLUGS`.
To publish another free report: add its slug here and in the app's `DEFAULT_FREE_REPORT_SLUGS`, apply, then sync.

## Public ledger (static, public)

`/ledger` and `/ledger/*` (`local.public_static_paths` in `tofu/cdn.tf`) are static behaviors placed with the
free reports, ahead of the gated `/reports/*` rule and every app behavior, so the ledger never reaches the
Lambda; the index-rewrite function 301s `/ledger` to `/ledger/` and `/ledger/testnet` to `/ledger/testnet/`
(mainnet ledger at `/ledger/`, testnet demo ledger at `/ledger/testnet/`). The files under `s3://nearbi-site/ledger/`
are owned by **rs-ledger** (`bin/publish`: build, reconcile, upload with `Cache-Control: max-age=60`,
invalidate `/ledger/*`), so `bin/sync-site.sh` excludes `ledger/*` from its `--delete` sync.
